# Model context window

A model id can carry an optional manual context-window override (tokens), for providers that don't advertise `context_length` over `/models` — without it the desktop can't size the context gauge or the agent's auto-compaction.

The override is a **shared model definition** keyed by model id, so it is entered once and reused across every provider serving that id.

The same value fixes an incorrect gauge limit and helps the backend select a safe auto-compaction trigger. Compression is enabled by default with a 0.50 ratio; the installed backend raises it to at least 0.75 for windows below 512K, accounts for output reservations, and honors an optional token cap.

## Storage and propagation

The override lives once per model id in `model-definitions.json` (a [[src/main/models.ts#ModelDefinition]] keyed by `model`), not per attachment row.

`models.json` rows are pure provider attachments; [[src/main/models.ts#readModels]] merges the matching definition's `contextLength` (and display `name`/capabilities) onto every row at read time, so `resolveLibraryModelEntry` and the pickers still see a flat `contextLength`. Writers use [[src/main/models.ts#readModelsRaw]] so merged fields are never persisted back onto a row. Legacy per-row `contextLength` is hoisted into definitions once by [[src/main/models.ts#ensureModelDefinitionsMigrated]] (larger window wins on conflict), run from `listModels()`.

The value is entered via the per-model-chip **pencil** editor in [[src/renderer/src/components/ProviderKeysSection.tsx#ProviderModelsManager]] (writing `setModelDefinition`), or captured from the registry on pick. On activation, [[src/main/config.ts#setModelConfig]] writes or clears `config.yaml`'s `model.context_length` from the (merged) library entry — the single value both the gauge and the agent read; an absent override clears any stale value left by a previously-active model. Definitions are local-only, so Remote/SSH activation does not propagate the override (as before).

## Gauge resolution order

The context gauge resolves its window size as: config override (active model) → provider `/models` `context_length` → static heuristic.

[[src/main/model-discovery.ts#getModelContextWindow]] consults [[src/main/config.ts#getModelContextLengthOverride]] first, returning it only when it targets the model being asked about (so a stale value can't leak onto a different model id), before falling through to the authoritative `/models` lookup and finally the renderer's substring heuristic.

## Occupancy estimate when the provider omits usage

The gauge shows a chars/4 estimate from locally loaded messages immediately, including zero for a fresh chat. Provider occupancy takes priority once reported, and local fallbacks are explicitly marked estimated.

`contextUsage` in [[src/renderer/src/screens/Chat/Chat.tsx]] always passes occupancy and the known model limit, falling back to the static model window while discovery is pending. Its memoized local estimate is only needed before usage arrives. [[src/renderer/src/screens/Chat/hooks/useDashboardChatTransport.ts#estimateContextTokens]] counts bubbles, reasoning, tool arguments and results. Initial local estimates include the latest reply; completion-time prompt estimates exclude it. Only loaded rows are counted, so paged-out history, system instructions, schemas and attachments can make the real context larger. No new API request or billing/usage record is generated by this display fallback.

A heuristic denominator is labeled separately as estimated while model discovery is pending; its unknown-family fallback is 1,000,000 tokens (displayed as 1M). This is not a discovered limit.

A failed turn without usage keeps the prior reported occupancy. [[src/renderer/src/screens/Chat/contextUsage.test.tsx]] exercises the actual Chat data expression and mounted gauge before any response, zero occupancy, and transition to provider counts; [[src/renderer/src/screens/Chat/hooks/usageFromPayload.test.ts]] verifies both local and completion-time estimation.

## Auto-compaction settings

The compact settings use 11px text, 24px input/save controls and a native 13px checkbox to match the surrounding popover.

The opened context popover exposes native profile compression settings, not a duplicate frontend auto-send loop. A native checkbox enables compression and an optional positive integer sets its token ceiling.

[[src/renderer/src/screens/Chat/ContextCompressionSettings.tsx#ContextCompressionSettings]] lazily reads `compression.enabled` and `compression.threshold_tokens` using the existing profile-aware config IPC. Save writes the ceiling first, then enabled state, reads both back, and only reports success after verification. Empty clears the cap to `null`, keeping the backend ratio policy. Failures replace the editor with an error so partial writes cannot masquerade as success. [[src/renderer/src/screens/Chat/ContextCompressionSettings.test.tsx]] covers persistence, reopen, validation, failed writes and failed verification.

Settings are profile-wide for new sessions; the installed gateway freezes compression in an existing session policy. No forced restart or live-session mutation is performed. Remote and SSH connections hide the editor: their generic config paths cannot safely persist these native scalars. Local settings use [[src/main/config.ts#setConfigValue]] with validated unquoted boolean, integer and null values. [[src/main/config.test.ts]] verifies scalar types, missing keys and invalid input.

[[src/renderer/src/screens/Chat/ContextGauge.tsx#ContextGauge]] waits for the existing `/compact` command promise, shows progress, disables duplicate compression and new-session actions while pending or streaming. Compaction is model summarization plus committed history persistence, not an instantaneous local trim. The bounded scrollable panel uses existing theme tokens, wraps help text, mounts settings only after a click, and supports Escape. [[src/renderer/src/screens/Chat/ContextGauge.test.tsx]] exercises the busy lifecycle and lazy panel mount.
